# Lumen · 墨光

Lumen 的基础表面透明，黑色或白色背景由宿主提供。在黑色背景上用灯带指示动作与状态，在白色背景上用墨条承担同一职责。两种模式都有外发光：白光向外散射，黑墨向外扩散。纯色用于文字、线芯、墨条和强调状态。MUI 提供组件概念与交互契约，Lumen 决定视觉表达。

黑白是默认预设，不是固定配色限制。主题通过 `LumenAppearance.colors` 独立配置 foreground（前景、灯条及外发光）、background（宿主背景）、contrast（强调填充上的反差文字）及可选的辅助/语义色。组件从这些颜色派生边界和扩散；不在变体内部写死白灯或黑墨。`LumenProvider` 自身不涂背景，宿主显式使用 `--lumen-canvas`。

## 设计判断

| 维度 | 实施准则 |
| --- | --- |
| 至简 | 每个区域突出一个当前动作。先用对齐、字重和间距建立层级，必要时才增加背景、边框或图标。 |
| 光感 | 两种主题均保留清晰实心线芯，周围产生柔和外发光：深色是白光散射，浅色是黑墨扩散。正文保持锐利。悬停、焦点、选中、运行有明确强弱，静态装饰不持续闪烁。 |
| 无界 | 常规内容共享背景，以标题与间距分组；边界只出现在需要辨识的输入、选择、滚动区域或覆盖层。无界不等于看不见焦点或点击范围。 |
| 扁平 | 不用立体投影或层层嵌套卡片表达普通层级。默认表面透明，依靠宿主背景；线芯外发光是局部状态表达，玻璃/磨砂是可选的覆盖层材质。 |
| 信息对比度 | 主信息最清晰，辅助解释次之，装饰最弱。普通文本至少 4.5:1、大文本至少 3:1；必要的控件状态/焦点至少 3:1。不要靠整体透明度降低正文可读性。 |
| 信息呈现 | 连续语句保持同一文本流；标题、正文、元数据按阅读顺序组织。行尾动作归属于原记录，用户消息可在居中阅读列内靠右。Badge 是数量/状态，Chip 是分类/可移除条件，Tab 是视图切换。 |
| 辅助框架 | 使用“稳定导航 + 内容区域 + 按需工具区”。工具栏跟随所属栏目，错误/加载反馈靠近触发动作。一个分隔线或局部条形指示通常足以表达框架。 |
| UI 原语 | 组合 Provider、Surface、Indicator、Text、Button、Field、List、Chip、Badge、Tabs；先修共享原语，再处理独立变体的布局。数据和文案由宿主提供。 |

## 在项目中实施

已确认正确的初版参照是视觉基线，不是待重写的占位稿。新增规则先落实为局部、可验证的改进；禁止借“统一风格”批量替换已有按钮、输入、开关、表面材质或默认主题。自定义主题必须显式启用，清除配置后恢复原有默认样式。

从 `packages/lumen-app-ui/src/ui/index.ts` 核对实际公开 API。宿主从 `@lumen/app-ui/ui` 导入控件，在 `LumenProvider` 中使用，并加载一次 `@lumen/app-ui/styles.css`。不要依据这份技能假定所有 MUI 组件已经迁移。

- 设计 token、灯带、表面或信息层级：读 [视觉原语](references/primitives.md)。
- 改造基础控件、核对 MUI 行为和覆盖缺口：读 [组件映射](references/components.md)。
- 样式来源：`styles.css`、`primitives.module.css`、`materials.module.css`、`forms.css`、`ui.css`。`theme.ts` 是 MUI 适配层，不应成为应用组件的第二套主题。
- 变体只描述内容与布局；不要在每个变体中重写主题色、光晕或控件状态。保留既有公开 props 的兼容性，新增的文案使用类型化宿主契约。
- 沿用项目的语义图标等级、自然 flex 流和本地化约定。仅实际覆盖层及附着在控件边缘的装饰可以定位；文字和按钮不靠坐标排版。

## 验收依据

灯条首先表达交互，不是结构装饰。以对齐、margin、padding 组织界面；小结构尽量无边界，大结构的静态边界低对比。可拖动的滚动条、可伸缩的分隔边界必须保留可辨识的操作范围；表格已有的必要网格线也不能为了“无界”删除。按钮在适合布局的一条边上发光（优先下边，允许上/左/右），静态标签不冒充按钮。禁用和接近零的进度用减弱亮度、不发光表达；接近满值的进度可以增强光感。

相邻灯条的美感来自对齐和统一尺度。先给同组控件建立匹配的尺寸，再按状态变化；不让短文本和长文本任意决定一排灯条的长度。线芯保持直线，不沿圆角折弯，也不把每个卡片描成发光框。弹窗/主要浮层是例外：用模糊、玻璃、外发光和可见外边界与下层拉开层次，正文仍然锐利。

所有有意设计的状态动画必须平滑：灯条长度、亮度、颜色、光晕、滑块位置和进度值连续插值；快速反向操作从当前呈现值继续，不先跳到端点。选中/取消、运行/停止和禁用不能靠条件卸载灯条或 `display: none` 跳变。呼吸动画与状态过渡分层，淡入淡出时不抢写同一个 opacity。禁止 `transition: all`；列明实际变化的属性。减少动态效果偏好和宿主 motion 关闭是明确的无障碍例外，不强迫用户观看动画。

在深色和浅色模式检查静止、悬停、键盘焦点、选中、禁用、加载和错误。两种模式都有可调外发光，关闭 glow 后线芯仍清晰。透明表面应透出宿主背景。尊重减少动态效果和强制颜色模式。

检查桌面与窄屏、长中英文内容、空列表及滚动边界。组合框检查方向键移动、Enter 提交、Escape 关闭；列表行内按钮不能同时触发行选择。几何检查和人工截图检查都需要：没有横向溢出不代表内容排列正确。

运行与改动相称的 lint、类型检查、交互测试和构建。动画需在真实浏览器采样开始、中间、结束以及中途反向的值，不只断言存在 transition 声明。设计预览使用同一公开原语；列出本次实现范围和仍未覆盖的 MUI 概念，不把一张效果图称为全量组件支持。
